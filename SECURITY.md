# Security Policy

## Reporting a vulnerability

Please report suspected security vulnerabilities privately.

**Do not open a public GitHub issue for an unpatched vulnerability.**

Until WerkZ publishes a dedicated security address, use:

**patslu@icloud.com**

Suggested subject:

`[SECURITY] WerkZ vulnerability report`

Please include, where possible:
- affected component/product;
- affected version or URL;
- clear reproduction steps;
- observed and expected behaviour;
- security impact;
- whether you believe exploitation is active;
- any logs/screenshots that do not contain third-party secrets or personal data.

Do not send passwords, private keys, customer credentials or unrelated personal data.

## Response process

WerkZ will:
1. acknowledge and validate the report;
2. assess affected versions and impact;
3. contain/remediate where necessary;
4. prepare and verify a security fix;
5. coordinate customer/advisory communication where appropriate;
6. assess applicable legal/regulatory reporting duties.

Timelines depend on severity, exploitability and affected product/deployment. This policy does not create a contractual SLA.

## Safe testing expectations

Please avoid:
- accessing or modifying data belonging to other users or organisations;
- destructive testing;
- denial-of-service testing;
- social engineering;
- persistence/backdoors;
- public disclosure before a reasonable remediation opportunity.

If validation requires access beyond your own account/environment, stop and contact WerkZ first.

## Supported versions

Supported product/version information will be maintained as WerkZ production release channels are established. Do not assume every historical build remains supported indefinitely.
